## 分项判定细则（逐条可执行）

### 第 1 项 · ADR（1.2）

```bash
# 数七个段落是否齐全
grep -nE "^## (状态|背景|备选|决策|trade-off|后果|评审)" adr/ADR-001-application-idempotency.md
# 数备选个数（应 ≥2）
grep -nE "^\s*\|\s*(方案|优点|缺点|适用场景)" adr/ADR-001-application-idempotency.md
```

- 备选只写名字不写四列的，判「缺备选」；
- 后果段没点到具体文件 / 类 / 表约束名的，判「后果不具体」；
- 「待验证项」还留着的，判「未闭环」。

### 第 2 项 · architecture.md（1.0）

```bash
# 契约小节是否只有标题没有内容
grep -n "待补" docs/architecture.md          # 结果必须为空
# 8 个契约小节标题是否都在
grep -cE "^### 4\.[1-8]" docs/architecture.md   # 必须等于 8
# 失败路径表数量
grep -cE "^\*\*失败路径\*\*" docs/architecture.md  # 必须等于 8
```

### 第 3 项 · dependency + spike（0.8）

- 依赖图必须能回答「谁调谁」，只有箭头没有模块名的图不算；
- 循环检查必须给**结论句**，不能只贴图；
- 风险表八类缺一类即该条不计分；
- spike 三个探针结论栏出现「待跑」即不得分。

### 第 4 项 · 契约可执行性（0.6）

- 对照表格式要求：`契约条目 | 对应 spec 文件 | 对应 AC 编号 / 边界行号 | 是否一致 | 待修则写改哪一条`；
- 拆任务演练抽样 3 个模块，记录问答原文进本表附件。

### 第 5 项 · 零业务代码（0.4）

```bash
git ls-tree -r main -- src/ tests/
git log --all --diff-filter=A --name-only -- "*.java" "*.vue" "*.ts" "*.sql" | head -50
```

- 出现任何非 README 的业务文件即不得分；
- 出现即同时触发红线扣分。
