# Spike 02：接口契约 Mock（M4 409 / M6 幂等重复触发）

## 1. 验证目标
通过静态 Mock 模拟 M4 的 409 响应与 M6 的幂等结果，验证前端表现，并核对契约字段。

## 2. 动作与预期前端表现
### 2.1 M4 投递登记 409 Mock
前端发送两次相同的投递请求，第二次返回 409 Conflict。

```json
{
  "code": "ALREADY_APPLIED",
  "message": "您已投递过该岗位，请勿重复提交"
}
```

**预期表现**：页面出现可见提示（Toast），按钮置灰防连点。

### 2.2 M6 面试提醒幂等 Mock
（注：M6 无 409，幂等靠唯一约束拦截，因此 Mock 为 200 返回）

```json
{
  "code": "OK",
  "data": { "nodeType": "D3", "sendStatus": "SENT" }
}
```

**预期表现**：同一节点只发一次，不重复弹通知。

## 3. 契约字段差异清单
- **契约多余字段**：M4 响应体中的 `requestId` 对前端展示无用，仅用于后端排障。
- **契约缺失字段**：M6 缺少 `reminderId`。若前端需手动“忽略”某条提醒，缺少该主键无法发起请求。建议在 4.6 契约中补上。

## 4. 结论
静态 Mock 通过。M4 前端需增加防抖与 409 弹窗捕获；M6 需在契约中补充 `reminderId`。
