| M5 文字模拟面试 | 生成面试问题、接收回答、四维评分与反馈、归档 | 不排真实面试；不发提醒；不做语音 | module-05 | 卢果 |

| M7 面经外链 | 面经链接收录、分组展示、24 小时失效探测、点击 3 秒判失效 | 不抓正文；不做全文检索；不评分 | module-07 | 熊尚华 |
| M8 求职档案看板 | 聚合展示投递漏斗、面试日程、复盘统计，只读 | 不写业务表；不判断规则；不做业务编辑 | module-08 | 熊尚华 |

## 2. 架构全景（四层）

展示层（Vue 3 + Vite + TypeScript + Pinia + Element Plus）
  ↓ HTTP / JSON
API 层（Spring Boot 3.x Controller）
  ↓ 调用 Service
服务层（Service · 业务规则唯一归属地）
  ↓ 调用 Mapper
数据层（MyBatis-Plus + MySQL 8.0 · RDS 独立部署）

| 层 | 职责 | 关键组件 |
|---|---|---|
| 展示层 | UI 交互与数据展示，只消费 API 响应 | 简历上传页、问卷页、岗位推荐页、投递看板、模拟面试页、面试登记页、面经页、档案看板 |
| API 层 | 接收请求、参数校验（Bean Validation）、JWT 鉴权、统一响应体与错误码、限流 | 8 个 Controller，按 M1–M8 一一对应 |
| 服务层 | 核心业务规则：10MB 校验、画像计分、匹配排序、投递状态机与幂等、5 节点提醒计算、四维评分、看板聚合 | 8 个 Service；事务边界只在这一层 |
| 数据层 | 持久化与增删改查，RDS 独立隔离，不与业务代码混部 | 8 个 Mapper + 只读视图 v_dashboard |

**四条层间约束（不可违反）**

1. 展示层只消费 API 响应，不判断业务规则（如不在页面判断「是否超过投递上限」）
2. API 层不写业务规则，只做校验、鉴权、编排
3. 服务层不渲染页面、不拼接 UI 文案结构
4. 数据层不处理 UI、不做业务判断

**依赖方向**：展示层 → API 层 → 服务层 → 数据层，单向，禁止反向与循环；展示层禁止直连数据层。

## 3. 核心数据实体

| 实体 | 说明 | 关键约束 |
|---|---|---|
| student | 学生账号 | 学号唯一 |
| resume | 简历与解析结果 | 每个学生一份有效简历 |
| holland_profile | 霍兰德六维画像 | 与 student 一对一 |
| job | 岗位外链元数据 | 外链失效标记 |

| interview | 面试登记 | 含开始时间与出发时间 |
| reminder | 提醒任务 | 唯一约束 (interview_id, node_type)，防重复触发 |
| interview_note | 面经外链 | 失效探测时间戳 |

## 5. 数据流

> 每个模块写两条路径。失败路径必须交代三件事：写不写库、已有数据动不动、能否重试且不产生重复记录。

### 5.1 M1 简历上传与解析

**成功路径**
1. 展示层选择文件 → API 层 `POST /api/resumes`
2. API 层校验：扩展名 ∈ {pdf, docx}，大小 ≤ 10MB
3. 服务层抽取纯文本 → 调用大模型结构化输出 → JSON Schema 校验
4. 写 `resume` 表（同一学生覆盖更新）→ 返回解析结果
5. 展示层进入确认页，学生可修正后保存

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 文件 > 10MB | 413 `FILE_TOO_LARGE` | 不落库，不留临时文件 | 换文件重试 |
| 扩展名不在白名单 | 415 `UNSUPPORTED_FILE_TYPE` | 不落库 | 换文件重试 |
| 大模型超时 | 504 `LLM_TIMEOUT` | 不落库，原 resume 不变 | 可重试，重复上传覆盖同一条，不新增 |

### 5.2 M2 霍兰德问卷与画像

**成功路径**
1. 展示层提交 30 题答案 → `POST /api/holland/answers`
2. API 层校验题数与选项合法性
3. 服务层计分（RIASEC 六维）→ 按 `student_id` upsert `holland_profile`
4. 返回六维画像 → 展示层渲染雷达图

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 题数不足 / 选项越界 | 400 `QUESTIONNAIRE_INCOMPLETE` | 不写库，原画像不变 | 补齐后重试 |
| 重复提交 | 200，覆盖更新同一画像 | 记录数不增，不产生第二份画像 | 幂等 |

### 5.3 M3 岗位推荐与外链

**成功路径**
1. 展示层请求推荐 → `GET /api/jobs/recommend`
2. 服务层读 `holland_profile` → 按六维匹配度排序
3. 返回岗位列表（含外链）→ 展示层渲染，点击跳外链

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 尚未生成画像 | 404 `PROFILE_NOT_FOUND` | 不写库 | 做完 M2 后重试 |
| 无匹配岗位 | 200 + 空数组 | 不写库 | 空结果是正常态，不是错误 |
| 外链已失效 | 200，该条带 `link_status = INVALID` | 标记失效，不物理删除 | 列表仍返回，前端置灰 |

### 5.4 M4 投递状态登记

**成功路径**
1. 展示层提交投递 → `POST /api/applications`
2. API 层校验岗位存在
3. 服务层按唯一约束 `(student_id, job_id)` 判重 → 写 `application`，状态 = 已投递
4. 返回投递记录

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 重复投递同一岗位 | 409 `DUPLICATE_APPLICATION` | 不新增记录，原记录不变 | 不可重试 |
| 非法状态流转（如 已结束 → 已投递） | 409 `INVALID_STATE_TRANSITION` | 状态字段不动 | 不可重试 |
| 并发两次提交 | 409，仅一条写入成功 | 唯一约束兜底，不会产生两条 | 幂等 |

> M4 是本项目并发最敏感的一处，由 ADR-001 决策覆盖。

### 5.5 M5 文字模拟面试

**成功路径**
1. 展示层开始面试 → `POST /api/mock-interviews`
2. 服务层生成问题 → 学生逐题作答 → 四维评分
3. 写归档记录 → 返回评分与反馈

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 大模型超时 | 504 `LLM_TIMEOUT` | 不写归档，会话可继续 | 可重试 |
| 四维评分缺项 | 200，标记 `score_status = PARTIAL` | 归档标不完整，不伪造分数 | 可重评 |
| 归档写失败 | 500 `ARCHIVE_FAILED` | 不留半条归档，按会话 ID 幂等重写 | 可重试，不产生两条归档 |

### 5.6 M6 面试登记与多级提醒

**成功路径**
1. 展示层登记面试（公司 / 岗位 / 开始时间 / 出发时间 / 地点）→ `POST /api/interviews`
2. 服务层按开始时间与出发时间计算 5 个触发点：前 3 天、前 1 天、前 2 小时（按出发时间）、前 30 分钟、结束后复盘
3. 写 `interview` + 5 条 `reminder`（唯一约束 `(interview_id, node_type)`）
4. 调度器到点发送

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 开始时间早于当前 | 400 `INVALID_INTERVIEW_TIME` | 不写库，不生成提醒 | 改时间后重试 |
| 改期 | 200，旧 5 条提醒全部置失效 | 按新时间重算，旧触发永不发出 | 幂等 |
| 同一节点重复触发 | 唯一约束拦截 | 同节点仅一条，只发一次 | 幂等 |
| 发送失败 | 记录 `send_status = FAILED` | 重试只更新状态，不新增 reminder | 可重试 |

> 5 次触发口径来自第 2 周定稿 spec，不得退回 4 节点。

### 5.7 M7 面经外链

**成功路径**
1. 展示层提交链接 → `POST /api/interview-notes`
2. API 层校验 URL 格式 → 写 `interview_note`（含 24 小时探测时间戳）
3. 展示层按公司 / 岗位分组展示

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| URL 非法 | 400 `INVALID_URL` | 不写库 | 改链接后重试 |
| 24 小时探测失败 | 200，标 `link_status = INVALID` | 只更新状态与探测时间，不删记录 | 次日再探测 |
| 点击 3 秒无响应 | 前端判失效并提示 | 不改库 | 用户可手动作废 |

### 5.8 M8 求职档案看板

**成功路径**
1. 展示层请求 → `GET /api/dashboard`
2. 服务层并行读 `application` / `interview` / `reminder`，聚合只读视图 `v_dashboard`
3. 返回各分区数据 → 首屏 3 秒内渲染

**失败路径**

| 情形 | 返回 | 数据影响 | 可否重试 |
|---|---|---|---|
| 单分区查询超 1 秒 | 200，该分区标 `status = TIMEOUT` | 不写库 | 可刷新重试 |
| 首屏 3 秒未完成 | 200，返回已完成分区 + 标失败分区 | 不写库 | 可刷新重试 |
| 任意失败 | 绝不返回编造的兜底数据 | 只读，全程零写库 | — |
