## 一、仅依据该文件的回答

**页面中断 loading，提示「网络异常，请重试」，并把作答草稿暂存；评分不能填 0。**

依据边界与异常的第一条，原文已经写全：

> 接口请求超时时间固定为 30 秒，失败重试最多 2 次，重试间隔 1 秒；若仍失败，前端中断 loading 并提示「网络异常，请重试」，暂存作答草稿，**不得直接记为 0 分**。

三件事都能唯一确定：页面表现（中断 loading + 具体提示语）、草稿处理（暂存）、评分处理（禁止填 0）。这条与 `agent-rules.md` 的「超时 30 秒、重试 2 次、间隔 1 秒」完全一致。

## 二、判定与缺陷

- 无阻断性缺口。**这份对超时场景的表述是 8 份里最完整的一份**，可以直接照做。

## 三、可选改进

1. 「暂存作答草稿」的存放位置未写（前端 localStorage 还是服务端草稿表），冷启动者实现时仍需一次决策。
2. 同文件另一处写「若某维度题目用户未作答或关键词完全未命中，该维度得分记为 0」——与超时不同场景，但两处都以「0 分」为关键词，建议在超时条目后加一句「与未作答记 0 区分：超时不产生得分记录」，避免实现时混淆。

**仅依据该文件的回答**

本模块不调用大模型：摘要写明「系统从题库按岗位类型抽取题目」，FR-3 为「从预置题库中抽取 5-8 道题」，FR-5 为「关键词匹配计算得分」，Non-Goals 明确「不接入大模型进行实时题生成」。因此提问中的「大模型 30 秒没有返回」在本模块内没有对应对象，只能由读者自行把「大模型」替换成「接口」，再按 NFR-1 与边界表第一条作答：中断 loading、提示「网络异常，请重试」、暂存作答草稿、不得直接记为 0 分。

评分部分可唯一确定：不得直接记为 0 分。

**判定：不可回答（提问对象在本模块中不存在）。**&#8203;

**缺口**

1. 是否调用大模型四处表述矛盾：摘要、FR-3、FR-5、Non-Goals 指向题库+关键词方案，NFR-1 与边界表第一条却按「接口请求超时 30 秒、重试 2 次」设计。
2. 提问所指的「大模型」在文档中无对应物，读者必须自行将「大模型超时」翻译为「接口超时」才能作答；若实现方按「存在大模型调用」理解 NFR-1，会为题库抽题写出一段不存在的超时重试逻辑。
3. 边界表出现「四维评分缺项」，但全文没有任何 FR 或 AC 定义四维是哪四维、如何计分。
4. 两个「0 分」含义不同但表述冲突：边界表第一条「不得直接记为 0 分」（超时场景）、第二条「该维度得分记为 0」（未作答或未命中场景）。

**据此需要修改的 spec 条目**

- NFR-1 与边界表第一条：先明确本模块是否调用大模型。若维持题库+关键词方案，删除大模型相关表述，改为「抽题与评分接口超时 30 秒、重试 2 次、间隔 1 秒」；若改由大模型生成题目，则 FR-3、FR-5、Non-Goals 三处须同步改写。
- 边界表第二行：补齐「四维评分」的定义（四维名称、计分规则、缺项口径），或删除该行。
- 边界表第一条末补一句，区分「超时不产生得分记录」与「未作答记 0 分」。
