## 一、仅依据该文件的回答

**这条记录不存在投递状态——系统不会因点击外链自动创建或变更投递状态，该岗位在学生的意向清单里没有条目，直到学生手动登记后才产生「已投递」。**

依据：

1. AC-4：Given「学生点击了外部岗位链接」，When「返回系统查看」，Then「该岗位状态不得自动变为『已投递』，必须由学生手动登记」。
2. FR-3 同义重申「点击外链跳转时，系统不得自动将该岗位记为『已投递』，必须由学生手动确认或操作登记」。
3. 摘要首句「点击外链不自动记为已投递」。

因此本题的答案是「无状态 / 无记录」，而不是四个状态中的任何一个。

## 二、判定与缺陷

- 主路径可回答，冷启动者不会误实现成「自动记为已投递」。

**残留边界（不阻断，但会让实现分叉）**：点击外链这一动作本身**是否留下记录**，文件没有写。`context.md` 术语表定义了「跳转记录 = 跳转时留下的检索条件，不含岗位详情」，但 M4 未引用该术语。冷启动者可能实现成「什么都不留」，也可能实现成「留一条跳转记录」。

## 三、修复建议

补一句：「点击外链仅写入跳转记录（检索条件，不含岗位详情），不创建投递记录；投递记录由学生手动登记时创建，初始状态为『已投递』。」

## 五、复验（2026-11-08，基于 9722a6ff）

### 复验结论
Q1、Q5、Q6、Q7 均能给出唯一答案，状态流转的穷举、错误码命名、终态规则三块写得清楚。Q2、Q3、Q4 暴露三处缺口，其中 Q4 为文档内部矛盾。

### 七问原始回答
- **Q1** 登记学生对岗位的投递状态并维护其合法状态流转。
- **Q2** 文档没有写用户从哪里进入，也没有写「最后从哪里出去」的入口/出口流程。文档只写了：学生点击外部岗位链接后返回系统查看时，该岗位状态不得自动变为「已投递」，必须由学生手动登记。
- **Q3** 文档写到的失败情况有两种：重复登记（拦截并提示「已登记」，返回 409, ALREADY_APPLIED）、非法状态流转（拦截并提示错误，返回 409, INVALID_STATUS_TRANSITION）。另外 AC-4 是禁止自动流转，文档没写这种情况用户会看到什么提示。
- **Q4** 不能。按 FR-2，「已投递」只能变更为【已查看】或【已结束】，禁止变更为【已约面】。AC-1 写的「已投递→已约面」与 FR-2 的流转规则冲突，文档未说明以哪条为准。
- **Q5** 不负责爬取或同步外部招聘平台的实际投递进度；不负责替代 BOSS 等平台的官方状态回传。
- **Q6** 返回状态码 409，错误码名字 ALREADY_APPLIED。
- **Q7** 不能。按 FR-2，「已结束」为终态，禁止变更为任何其他状态。

### 据此修改的 spec
- 摘要补一句：入口为 M3 岗位推荐列表点击「登记投递」进入，出口为 M8 看板投递记录区。
- AC-4 补 Then 末尾：页面不出现任何「已投递」状态变化，并在返回时提示「请手动确认是否已投递」。
- **FR-2 修正**：删除「已投递：禁止变更为【已约面】」，改为「已投递：可变更为【已查看】【已约面】或【已结束】」，与 AC-1 对齐。
