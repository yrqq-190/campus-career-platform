# Agent 评审通道（第 10 周）

> 维护：颜睿卿（记录 / 看板）｜建立：2026-11-26（D1）
> 对应：PPT P12「S8 上：Agent 评审 + 人工评审分工」、P16 评审记录模板、P20 检查表

## 1. 三条通道，按可用性选

| 通道 | 触发方式 | 本周是否可用 | 说明 |
|---|---|---|---|
| A. Copilot code review | 仓库设置里开启后自动评审 PR | 否 | 需要 Copilot 订阅（仓库当前没有），开启入口在 Settings → Copilot |
| B. 本仓 Action `PR 结构自检` | PR 打开 / 编辑 / 推送即触发 | 是（已启用） | 只查结构、分支名、改动文件清单，**不做内容判断** |
| C. 人工 `@Agent` 评审 | PR 评论里 @ 一个可用的 Agent，附五项检查结论 | 是（兜底） | 结论与截图存进 `docs/review/pr-XX.md` |

本周采用 **B + C**：B 兜住格式与范围底噪，C 做五项检查的内容判断。A 不可用不视为缺项，但评审记录里要写明「Agent 评审通道 = 自建 Action + 人工 @Agent 截图」。

## 2. 通道 B 做了什么

`.github/workflows/pr-structure-check.yml`，无密钥、只用 `GITHUB_TOKEN`：

- 读 PR 描述，检查 8 项：关联 Issue 与 AC、变更摘要、AI 使用说明、测试证据、变更范围、风险与回滚、评审清单、分支命名 `前缀/issue-N`；
- 拉改动文件清单（状态 + 行数），供人工核对范围收敛；
- 在 PR 下发**一条**带标记的评论，重复触发时更新同一条，不刷屏；
- 关键项（Issue/AC、变更摘要、分支命名）缺失时 job 失败，PR 上显示红叉；提示项只列 ❌，不阻塞。

## 3. PPT P12 五项检查：谁来做

| 检查项 | 通道 B | 人工 / Agent |
|---|---|---|
| 测试真正运行并通过 | 只能看出描述里有没有证据段 | 看证据是否可复现：命令、分支、提交、输出 |
| 改动范围收敛 | 列文件清单与行数 | 逐文件 `git diff --stat` 核对是否越界 |
| 未触碰白 / 黑名单 | 能看到文件路径 | 判断路径是否属他人模块、是否改 `spec/` 冻结内容 |
| 无幻觉 API / 依赖 | 做不到 | 核对调用是否存在、依赖是否已批准 |
| 无 spec / AC 偏离 | 做不到 | 对照 spec 逐条 AC 判定 |

## 4. D3 操作顺序（评审人照做）

1. PR 提交后先看通道 B 的评论，关键项有 ❌ 直接退回补描述，不进内容评审；
2. 在 PR 评论 @Agent，输入三件套：`@spec/...` + `@docs/agent-rules.md`（或 `CLAUDE.md`）+ 当前分支名，要求按五项检查给结论，**保留截图**；
3. 人工逐文件 diff 与测试证据复核，结论只能由人给：通过 / 整改 / 阻塞；
4. 写 `docs/review/pr-XX.md`，Agent 评审结果与人工裁决分栏记录，整改项标「代码 / 测试 / spec」。

## 5. 边界

- 通道 B 的绿勾**不是合并许可**；PR 至少 1 人 APPROVED，且评审人 ≠ 提交人 ≠ 主笔（`docs/pr-gate.md` 第 5 条）。
- 通道 B 失败不自动阻止合并，但关键项红叉状态进评审记录，作为 D4 检查表「PR 模板字段齐全」的依据。
- 后续若开通 Copilot（通道 A），保留 B 作为格式兜底，两者不冲突。
