## 四、AC 逐条结论

- **AC-2（确认后写入、以提交内容为准）**：对上。`confirmOk`、`confirmUsesSubmittedContent`（暂存区反证）、`currentConfirmed`、`uploadThenConfirmThenCurrent` 覆盖端点与三端点全链路；生产代码 confirm 经 `ResumeArchiveService`，upload 的校验与解析链路未动。
- **AC-4（部分类别为空返回空数组、不省略字段）**：对上。`currentConfirmed` 断言 internships 为空数组；`ResumeView` 字段与 `ParsedResume` 对齐。
- **AC-8（全空 → 422 `NO_VALID_FIELD`、不生空档案）**：对上。`confirmAllEmpty` 断言 422 且仓库无写入；Service 判空先于唯一写点，失败路径无写操作。
- **AC-9（失败不破坏现有档案）**：**本 PR 不单独宣称闭合**。字面路径「上传解析超时」由 #127（T3）的 `ResumeParseFallbackControllerTest.ac9ArchiveUntouched` 在 main 闭合（旧档案全字段、CONFIRMED 状态、画像侧读数均不变）；本 PR 的 `confirmFailureKeepsExistingArchive` 覆盖另一条路径——已有档案时 confirm 提交全空。两条共同要求「旧档案不被破坏」，AC-9 由两者合起来闭合，归属表述与事实一致。
- **附带**：FR-7 幂等（`confirmIsUpsert`）、学生隔离（`archivesAreIsolatedByStudent`）均对上。

## 七、设计取舍（记录备查）

`GET /api/v1/resumes/current` 的空态要求字面 `"data": null`，而公共 `ApiResponse` 是类级 `@JsonInclude(NON_NULL)`，null 键会整体消失。本 PR 照 4.2.4 `ProfileResponse` 的先例另造 `CurrentResumeResponse` 外壳，不改公共 `ApiResponse`（改它会让失败响应也多出 `"data": null`，与 4.1.1「失败不带 data」相反）。两个模块空态外观因此一致。
