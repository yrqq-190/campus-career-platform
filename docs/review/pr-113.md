## 四、评审意见（3 阻塞 + 2 建议）

**阻塞项**

1. **`studentId` 可选 Query 参数越权。** §4.3.1 写「Header 带 JWT，无 body」，身份从 token 取；做成可选参数等于允许传任意学生 ID，且 M3 的越权口径（id 不存在或不属于当前学生一律 404）在此处没有校验点。要求：删参数，Controller 从 `SecurityContext` / `@AuthenticationPrincipal` 取当前学生。
2. **两种空态未区分。** AC-2（画像无技能标签，文案「暂无匹配岗位，请完善技能标签」，200 且带 `PROFILE_SKILL_MISSING`）与 AC-5（技能完整但无命中，文案「暂无匹配岗位」，200 不带标记）是两个边界；骨架只做一种，用了 AC-2 的文案却没有降级标记，两条 AC 都无法验证。要求：补 AC-2 的降级响应样例，并把 `PROFILE_SKILL_MISSING` 从错误码表移到响应字段说明。
3. **AC-3 做不出来。** AC-3 要求「卡片标记失效来源」并「提供关键词重检链接」，但 `JobItem` 无对应字段。要求补 `linkStatus`（`OK` / `INVALID`，沿用 §4.7 取值口径）与 `retryKeyword`。另：AC-3 的触发时机是「用户点击该外链」，而 §4.3.1 把 404 挂在列表接口，一条外链失效即整个列表 404——此条属契约缺陷，不是本 PR 的错，建议单开 spec 修订，骨架里不要按错的写。

**建议项**

4. **AC 覆盖声明补全。** 现写 AC-1、AC-5，端点实际承载 AC-1～AC-5 全部（AC-4 的演示标识已写在页面结构里）。
5. **第 6 节 Java 片段手拼响应。** 用 `Map<String, Object>` 未走 `ApiResponse`，缺 `message` 与 `requestId`；注释「#11 脚手架合并后直接移入 src/」引用有误——#11 是建表 Issue，不提供脚手架，公共层在 #119、#127。

## 五、结论与后续

骨架形态站得住：端点、五个字段、失败码与冻结契约零漂移，页面结构还把 AC-4 的演示标识与空态文案补上了，比单贴 JSON 有实感。

但准入 8 条里前 4 条全部不通过——描述仅 340 字符，无 AI 说明、无验证证据、首行格式也不对；另有 3 个阻塞项会让 AC-2 与 AC-3 直接做不出来。因此本次给 **COMMENT 而非 APPROVED**，作者返修后我再 APPROVE 并合并。
