## 四、评审意见（3 阻塞 + 4 建议）

**阻塞项**

1. Java Mock 三个方法只 put `code` / `data`，缺 `requestId`；§4.7.1 的 200、§4.7.2 的 201 样例都带 `requestId`。骨架是冻结构用的，留空会被实现者照抄漏掉。要求：补 `requestId` 或在文档写明由 #11 统一壳注入，二选一。
2. 点击链路与 AC-4 冲突：`checkLink()` 不调 `/reachability` 直接 `window.open`，未探测过的死链打开后没有任何兜底；`INVALID` 记录按钮 `disabled`，学生点不到也就给不出 AC-4 要求的重检提示。要求：改成「先 GET /reachability → 可达才开窗；不可达弹重检」，`INVALID` 另设「重检」入口（同时满足 NFR-2 的置灰与 AC-4 的兜底）。
3. 前端未校验协议就 `window.open(note.url)`；后端 SSRF 防的是服务端抓取，不防浏览器跳转，`javascript:` 伪协议可执行。要求：打开前加 `^https?:` 校验（一行）。

**建议项**

4. `page` / `pageSize` 用 `int` 且只靠 `defaultValue`，落地建议 `Integer` + `@Min(1)/@Max(100)`，对齐 400 触发条件。
5. `Boolean isDemo` 的 Jackson 命名：record 在 Jackson 2.12+ 按组件名保留 `isDemo`，普通 getter 解析会变成 `demo`。建议 `@JsonProperty("isDemo")` 或写明 JDK/Jackson 版本前提。
6. 「分组展示」是 §4.7 表格原文，但契约无分组字段，建议限定为前端按岗位/来源分组，避免实现时多加字段。
7. 两个 422 前端不可区分，建议约定 `message` 两种固定文本（不改契约、不加字段）。

**第 4 条准入**：要求补静态检查命令与实际输出（围栏计数、字段 grep、`git diff --stat`）。

**AC 逐条**：AC-1 ✅（字段齐全，1 秒属 NFR-1 只声明不验）；AC-3 ✅（空态 + `personalizationApplied=false` 双样例）；AC-4 ⚠️（降级字段齐全，点击链路未接）；AC-5 ✅（`isDemo` + 「演示数据」标签）。

## 五、结论与后续

骨架质量在本周四份里属上乘：字段与冻结契约零漂移、边界口径（200 与 404 的分工、两个 422 分开）都写死了，docs-only 形态的理由也讲清楚。

但 3 个阻塞项里第 2 项不是笔误，是 AC-4 与 NFR-2 在 UI 入口上的真实冲突，必须靠「另设重检入口」解决；第 1 项属于骨架的核心职责（冻结构）。因此本次给 **COMMENT 而非 APPROVED**，作者返修后我再 APPROVED 并合并。
