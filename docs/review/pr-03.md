## 四、问题与建议

1. **契约缺口是本次评审最关键的发现**：architecture 4.2 五个端点里没有「填写意向城市与期望行业」的写入路径，而 AC-2 的 Given 与 4.2.3 响应都要求这两项有值。提交人处理方式是「只定义存储端口 + 测试注入，不自造端点」，判断正确——加端点等于改已冻结契约，须走「改 spec → 改 architecture 4.2 → 再实现」。**建议单开 Issue 记录该缺口**，方案二选一：给 M2 补意向填写端点，或把两项并入 4.2.3 请求体并同步改 FR-5。这件事下周开工前需要有人拍板，否则 AC-2 在真实链路里验不出来。
2. **第 6 条同 #120 一样空转**：评审人 APPROVED 但未写逐条 AC 结论。
3. **`SubmitResponse` 被改两次**（`SubmitResponse.java` +5/−5 在本 PR，+#120 已新建该 DTO）——属叠放分支的正常现象，但合并顺序必须严格 T4→T5，否则 4.2.3 的响应结构会短暂不一致。
4. **`SCORE_NOT_TRACEABLE` 只做单元级验证**：建议在 T3（#127）落地的失败链路稳定后，补一条从 HTTP 入口触发的集成用例，避免 500 分支长期无集成覆盖。
