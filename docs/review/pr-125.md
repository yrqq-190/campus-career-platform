## 三、 问题与建议（非阻塞）

1. **关于 5 次触发的时间基准**：`架构 4.6` 明确区分了「前 2 小时按出发时间算」，但当前 Mock JSON 中 `H2_DEPARTURE` 的 `triggerAt` 时间显示为 `10:30`，未体现出与出发时间字段的联动计算。建议在真实代码实现时补上 `departureTime` 字段的判空及降级逻辑（缺失出发时间时按开始时间兜底）。
2. **关于幂等与失败重试**：Mock 里写了 `REMINDER_SEND_FAILED` 报错，但没有体现“发送失败重试 3 次、间隔 5 分钟”的逻辑。建议在后续的 Service 层实现中，加入状态为 `FAILED` 的中间态，并在架构或序列图中注明重试机制。
3. **关于 409 冲突的覆盖**：当前 PR 的 Mock 测试用例只写了 201 成功和 500 失败，建议补充一个「改期导致旧提醒失效」或「重复登记同一节点 409」的 Mock 用例，这样能更完整地覆盖 M6 的边界异常表。
4. **字段命名对齐**：建议 JSON 返回的 `nodeType` 严格对齐 `D3 / D1 / H2_DEPARTURE / M30 / POST_REVIEW`，目前看 Mock 里已经是正确的，后续开发请保持。
