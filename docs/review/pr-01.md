## 四、建议改动（不阻塞合并）

1. **「Closes 部分 #103」写法需改**：GitHub 不识别「Closes 部分」，但该措辞易被后续维护者误读为可关；#103 尚有 AC-1、AC-2、AC-6、AC-7、AC-8 未完成。建议改为「关联 #103（不 Closes；解析链路与超时重试由后续 PR 完成）」。
2. **`nextResumeId()` 为占位实现**：当前用 `ThreadLocalRandom(1–999)` 拼日期，进程重启或并发下存在撞号风险，且该 ID 会返给前端引用。建议留 `TODO(T1)` 并在 T1 建表后改由库序列/自增生成，或先改进程内 `AtomicInteger`。
3. **`pom.xml` / `.gitignore` 属基建改动**：建议在 #11 脚手架卡登记，避免后续 PR 重复引入同一依赖版本。
4. **`AC-5` 的「损坏 PDF」补一条用例**：现有测试覆盖 0 字节，建议补「头部正确、内部截断的 PDF」用例，或在 PR 描述中把该场景标为未覆盖。
