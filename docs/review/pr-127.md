### 需 Spec Owner 裁定（准入第 8 条）

3. **502 是否做服务端自动重试。** 现状 504 / 502 共用同一重试循环、最多 3 次尝试、最终错误码取最后一次尝试原因，两处测试固化 `model.calls()=3`。广义依据：FR-4「失败最多重试 2 次、间隔 1 秒」未在文字上限定失败类型；架构 §5.1 失败路径表把 502 标为「可重试，不产生新记录」。反向依据：FR-4 重试表述与「调用超时固定 30 秒」在同一句，且只明确「超时重试耗尽返回 `PARSE_TIMEOUT`」，502 是同条后一分句、未写自动重试；spec 边界与异常表第 134 行写「校验失败即终止，不展示半成品」，AC-7 Then 仅规定「不展示任何字段、不入库」；架构 §4.1.1 的「重试入口」从上下文看是返回给前端的用户手动重试（仍调用 `POST /api/v1/resumes`），并非服务端循环次数。建议 Spec Owner 陈雪在 FR-4 / AC-7 或 §4.1.1 / §5.1 补一句明确口径：若服务端自动重试覆盖 502（并明确「先超时、末次为 502」的混合失败按末次错误码返回），则 spec 留痕、实现无需改；若裁定 Schema 失败快速失败，则调整 `ResumeParseService` 的 catch 分支（`MODEL_OUTPUT_INVALID` 直接抛出，仅超时与调用异常重试），并同步修改 `ResumeParseServiceTest.naturalLanguageBecomes502`、`ResumeParseFallbackControllerTest.ac7NaturalLanguage` 两处 `calls=3` 断言。另：调用本身失败（网关不可用 / 鉴权失败 / 连接异常）在 M1 封闭错误码集合下归为 502 `MODEL_OUTPUT_INVALID`（作者「口径三」）评审认可，符合「无新增码」；但该枚举默认文案「解析结果格式异常，请稍后重试」用于上游不可用成因时不够贴切，建议后续在不新增错误码前提下按成因覆盖 `message`。422 不重试（作者「口径二」，模型已正常返回、重试仍为空）评审认可，并有 `calls=1` 断言固化。

### 非阻塞建议

4. `MockResumeParseModel` 位于 main 源码且是当前唯一 `ResumeParseModel` 实现，`@Component` 未加 Profile 或条件装配，生产上下文也会装配并返回固定简历（忽略上传字节）；本周 Mock 阶段可接受、类注释已诚实标注，建议接入真实模型前加 `@Profile("mock")` / `@ConditionalOnProperty` 开关或启动期显著 WARN。
5. `ParseTrace` 仅保存最终 `errorCode`、`attempts`、`retried`，建议后续增加仅含元数据的 `attemptErrors` 以支持混合失败排障（不碰响应契约、不记录简历正文）。
6. 模型网关使用无界缓存线程池且无优雅关闭（守护线程不阻止 JVM 退出，类注释已说明）；后续建议改为有界池并加并发上限 / 背压与销毁关闭。
7. Schema 对 `internships` 元素仅要求是对象、无必填键（§4.1.1 成功示例中该数组为空），与 `projects` 必填 `name` 不对称；教育背景强制 `school / major / degree` 三个非空文本对稀疏简历或偏严，建议待契约补全实习对象示例与必填集合后以 spec / 架构变更同步校验，不在本 PR 凭空新增字段键。
8. 可补两个低成本测试：「首次调用失败、重试后成功」的恢复路径，以及「超时 → 502 混合失败取末次错误码」；非法重试参数拒绝已由 `ParseRetryPolicyTest.rejectsIllegalArguments` 覆盖，无需重复。
9. 跨 PR 观察（不计入本 PR 阻塞）：`docs/development.md` 仍写仓库无可运行构建入口 / 未提供测试命令，与 main 已有 `pom.xml`（Spring Boot 3.3.5 / JDK 17）和 80 个测试用例的现状不一致，建议另开 docs PR 更新（JDK 17、`mvn -Dfile.encoding=UTF-8 test`、当前为内存实现、无外部中间件）；按准入第 7 条不在本 PR 夹带无关文件修改。
