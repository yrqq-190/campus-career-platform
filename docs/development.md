# 开发说明

## 仓库内容

仓库包含产品说明、规格、架构决策与 GitHub 协作模板。`src/` 和 `tests/` 提供目录用途说明，不含可运行的前后端工程或业务测试。

阅读和修改 Markdown 与 YAML 文件不需要安装应用依赖。仓库未提供依赖清单、构建入口或部署配置，因此不应执行或传播不存在的应用启动命令。

## 技术方案

前端方案为 Vue 3 与 Vite，后端方案为 Spring Boot，业务存储方案为 MySQL。运行时版本、依赖管理、文件存储与部署配置应与工程实现一并记录，并说明选择依据。

技术方案说明不等同于已完成环境适配、接口联调或部署验证。引入可运行模块时，应同步提供依赖清单、安装步骤、环境变量说明与实际可执行的验证命令。

## 文档与模板维护

- 修改产品行为时核对 `context.md` 与相关规格的一致性。
- 修改路径或目录时更新相对链接与架构说明。
- Issue 表单位于 `.github/ISSUE_TEMPLATE/`，Pull Request 模板位于 `.github/PULL_REQUEST_TEMPLATE.md`。
- 模板提供问题与提案的填写结构；创建 Issue 与配置项目看板属于独立操作。
- GitHub 模板需要位于仓库默认分支对应路径，才能供新建 Issue 或 Pull Request 使用。

## 业务实现要求

运行配置应区分公开示例与本地凭据。环境变量名称可以在说明中列出，真实值不能提交；必要时使用不含凭据的示例配置，并确保版本控制规则允许提交该示例。

涉及外部平台或模型服务时，说明输入、输出、错误处理和本地替代方式。不得为通过演示而绕过权限检查或返回伪造的成功结果。

测试命令、构建命令及其依赖应通过实际执行验证。验收说明记录真实结果，不以模拟通过宣称外部服务已经可用。
