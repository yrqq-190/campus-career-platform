# 功能规格

功能规格描述用户能够观察和验证的行为，为设计、实现与验收提供共同依据。规格应覆盖输入条件、处理规则、输出、异常行为、数据访问约束与验收条件。

## 编写约定

每份规格聚焦一个明确功能，使用与 [项目上下文](../context.md) 一致的术语。外部服务返回值、演示数据与真实记录应明确区分，不能通过展示样例宣称完成端到端流程。

规则不明确时，应直接说明待确定的问题及其影响。跨模块变化需引用相关规格，避免同一状态、字段或提醒节点出现不同定义。

状态取值、字段名与字段形态以 [接口契约](../docs/architecture.md) 为准，规格给出的取值必须与契约同名同形。字段在契约里是数组，规格就不能只写单个值；状态枚举在契约里是 `PENDING_CONFIRM`，规格若要同时写中文展示名，必须把枚举值一并写出，不能只写「待确认」。

同一标识符是错误码还是响应内的标记，以该模块契约顶部的错误码说明为准，其余模块引用时必须沿用同一定性，不得一处称错误码、另一处称标记。

AC 允许两种写法：带标题与 Given/When/Then 分列，或单行 `- AC-x（类型）：Given…When…Then…`。同一模块内保持一致即可，全项目不强求统一。

一份规格被改动时，若改动涉及数据表结构，必须在 PR 中同时提出表结构变更请求并指明归属人，不得让契约先行、表结构滞后。
