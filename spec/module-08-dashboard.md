# module-08 求职档案看板

> 负责人：熊尚华｜阶段：D7（补 AC 与边界异常表）

## 摘要

本模块是 MVP1 求职链路的输出出口，依赖 M1–M7，把学生在各模块产生的数据
聚合成一份只读的求职档案看板，完整呈现「简历解析 → 求职画像 → 岗位推荐与
投递 → 模拟面试 → 面试安排与多级提醒 → 面后复盘」的全过程记录。看板按
求职画像、意向清单、面试安排、复盘记录等分区汇总，学生可一屏回看自己的
求职进展与待办；数据仅做聚合展示，不在本模块内新增或修改，任何编辑都回到
对应源模块完成。就业中心侧仅提供只读看板，用于定位「已投递未约面」
「约面未复盘」等状态，审核与导出功能后置到 P1，本版不提供。本模块不做
数据导出、不提供审核与编辑能力、不做企业端招聘管理、不做录用概率预测，
也不引入新的数据采集。

## 用户故事

- 作为求职的学生，我想要在一屏看到自己求职全过程的汇总记录，以便回看进展和待办。
- 作为求职的学生，我想要看到待办与关键状态（如已投递未约面、约面未复盘），以便及时跟进。
- 作为就业指导中心，我想要查看只读的学生看板，以便定位需要关注的学生。

## AC

- AC-1（正常）：Given 学生在 M1–M7 各模块已有数据，When 打开看板，Then 应按求职画像、意向清单、面试安排、复盘记录分区聚合展示完整链路。
- AC-2（正常）：Given 学生在看板点击某条记录要修改，When 系统响应，Then 看板不提供编辑，应跳回对应源模块完成。
- AC-3（边界）：Given 部分模块尚无数据（如还没约面），When 打开看板，Then 对应分区展示空状态、其余分区正常，不报错崩溃。
- AC-4（正常）：Given 存在「已投递未约面」「约面未复盘」等状态，When 看板汇总，Then 应突出这些待办与关键状态。
- AC-5（约束）：Given 就业中心账号打开看板，When 查看，Then 仅可只读浏览，不出现编辑、审核与导出入口。

## 功能需求

### US-1 → FR-1 ～ FR-2

**FR-1**：看板应聚合 M1–M7 的数据，按求职画像、意向清单、面试安排、复盘记录等分区展示完整链路。

**FR-2**：看板仅做只读聚合，不在本模块新增或修改数据，编辑操作跳回对应源模块完成。

### US-2 → FR-3

**FR-3**：看板应汇总并突出待办事项与关键状态节点，支持学生快速定位需要处理的环节。

### US-3 → FR-4

**FR-4**：就业中心侧仅提供只读看板，本版不提供编辑、审核与导出功能（后置 P1），也不做企业端管理。

## 非功能需求

## 边界与异常

| 场景 | 预期行为 | 对应 AC |
| :--- | :--- | :--- |
| 部分模块无数据 | 对应分区展示空状态，不崩溃 | AC-3 |
| 尝试在看板内编辑 | 禁止编辑，跳回对应源模块 | AC-2 |
| 就业中心尝试审核或导出 | 不提供入口，仅只读（后置 P1） | AC-5 |
| 源数据缺失字段 | 仅聚合已有数据，不新增采集 | AC-1 |
