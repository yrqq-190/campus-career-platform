# module-04 投递状态登记

## 摘要

本模块负责登记学生对岗位的投递状态，并维护状态流转。状态与流转条件以仓库现有 context.md / mvp-scope.md 中的定义为准；点击外链不自动记为已投递。

## 用户故事

- 作为求职的学生，我想要手动登记我在外部链接的投递状态，以便追踪我的求职进度并形成意向清单。
- 作为求职的学生，我想要在状态改变时（如收到面试通知）更新记录，以便管理我的求职档案。

## AC

- AC-1（正常）：Given 学生处于“已投递”状态，When 收到面试通知并操作更新，Then 系统应允许状态变更为“已约面”。
- AC-2（边界）：Given 学生对同一个岗位已经登记过投递记录，When 再次点击登记，Then 系统应拦截并提示“已登记”，返回状态码 409。
- AC-3（异常）：Given 学生当前状态为“已结束”，When 尝试将其改为“已投递”，Then 系统应拦截该非法状态流转，返回状态码 409。
- AC-4（异常）：Given 学生点击了外部岗位链接，When 返回系统查看，Then 该岗位状态不得自动变为“已投递”，必须由学生手动登记。

## 功能需求

- FR-1：系统需支持记录岗位的投递状态，状态包含四个：已投递、已查看、已约面、已结束。
- FR-2：系统需支持状态的合法流转（例如：已投递只能变更为已查看或已结束等），禁止非法的逆向跳转。
- FR-3：当学生点击外链跳转时，系统不得自动将该岗位记为“已投递”，必须由学生手动确认或操作登记。

## 非功能需求

- NFR-1：投递状态的变更操作需保证数据一致性，防止并发导致的状态错乱。
- NFR-2：状态记录需支持历史追溯（例如记录状态变更的时间）。

## 边界与异常

| 场景 | 预期行为 | 对应 AC |
| :--- | :--- | :--- |
| 非法状态流转 | 拦截操作，提示错误，返回 409 | AC-3 |
| 重复登记 | 拦截提交，提示“已登记该岗位”，返回 409 | AC-2 |
| 点外链自动记投递 | 禁止自动流转，必须手动确认 | AC-4 |

## Non-Goals

- 不负责爬取或同步外部招聘平台的实际投递进度。
- 不负责替代 BOSS 等平台的官方状态回传。
