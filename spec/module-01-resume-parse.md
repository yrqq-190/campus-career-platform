# module-01 简历上传与解析

> 负责人：贾小舒｜阶段：D6+D7（七章节已齐；AC 与边界表已按 D7 要求预先完成，待颜睿卿复核）

## 摘要

本模块负责把学生上传的简历文件转成结构化求职档案，是求职画像的数据起点。学生在建档页面上传 PDF 或 Word 格式的简历，系统保存文件后调用大模型抽取教育背景、专业技能、项目经历、实习经历四类字段，以结构化 JSON 返回前端渲染。解析结果必须经学生逐项核对与修改、由学生显式确认后才写入档案，机器识别结果不直接生效。格式不支持、文件超限、解析超时、模型输出无法通过结构校验、未抽到任何有效字段等情形，一律返回明确错误码与提示，不允许静默失败。本模块只覆盖简历的接收、解析、人工确认与替换，不生成求职画像、不做岗位匹配、不解析非简历文档，也不保存或比对多份简历的历史版本。

## 用户故事

**US-1 建档**
作为准备求职的在校学生，我想要上传我的 PDF 或 Word 简历并让系统自动抽出教育背景、专业技能、项目经历与实习经历，以便我不必从零手动填写就能得到一份可用的结构化求职档案。

**US-2 纠错确认**
作为担心机器识别出错的学生，我想要在解析结果上逐条修改并显式点击确认，以便识别错误的内容不会未经我同意就进入求职画像与岗位推荐。

**US-3 档案替换**
作为经历已有更新的学生，我想要重新上传简历来替换当前档案，以便后续的画像与推荐基于我最新确认的内容，而不是几周前的旧版本。

## 验收标准

> 格式统一为 Given / When / Then。AC-1、AC-2 覆盖正常链路，AC-3、AC-4 覆盖边界，AC-5 ～ AC-9 覆盖异常。

**AC-1 正常：完整链路解析成功**（对应 FR-1、FR-2、FR-4、FR-5、FR-6）

- **Given** 学生已登录，且当前没有任何正式档案
- **When** 上传一份 2 MB、内容正常的 PDF 简历并等待解析结束
- **Then** 前端在暂存区展示教育背景、专业技能、项目经历、实习经历四类字段，正式档案仍为空，档案状态显示为"待确认"

**AC-2 正常：确认后写入并在下游生效**（对应 FR-6、FR-7）

- **Given** 暂存区已有解析结果，且学生把"专业技能"中的一项从"Java"改为"Java、Spring Boot"
- **When** 学生点击"确认入库"
- **Then** 正式档案中的专业技能保存为修改后的内容，随后生成的画像读取到的是"Java、Spring Boot"而不是模型原始输出

**AC-3 边界：文件大小上限 10MB**（对应 FR-2）

- **Given** 系统允许的单文件上限为 10MB
- **When** 分别上传恰好 10MB 与 10MB + 1KB 的两份 PDF
- **Then** 第一份进入解析流程；第二份被拒绝，返回 413 与 `RESUME_TOO_LARGE`，提示文案为"单份简历不超过 10MB"

**AC-4 边界：四类字段部分为空**（对应 FR-5）

- **Given** 一份只写了教育背景、没有任何项目与实习内容的简历
- **When** 解析成功
- **Then** 项目经历与实习经历以空数组返回而非省略字段，学生可以对空数组新增条目，档案可以正常确认

**AC-5 异常：文件格式不支持或不可读**（对应 FR-2）

- **Given** 学生选择上传一张 .png 图片，或上传一个设置了打开密码的 Word 文档
- **When** 提交上传
- **Then** 均返回 415，图片返回 `RESUME_FORMAT_UNSUPPORTED`、加密文档返回 `RESUME_UNREADABLE`；不产生任何档案记录，学生原有档案不受影响

**AC-6 异常：模型解析超时**（对应 FR-4）

- **Given** 大模型连续三次均未在 30 秒内返回
- **When** 学生上传一份正常 PDF
- **Then** 系统按 30 秒超时、间隔 1 秒重试 2 次后放弃，返回 504 与 `PARSE_TIMEOUT`；前端提示"解析超时，请稍后重试"，正式档案保持上传前的状态

**AC-7 异常：模型输出不合法**（对应 FR-4）

- **Given** 大模型返回的是一段自然语言说明，而不是约定的 JSON 结构
- **When** 系统做 JSON Schema 校验
- **Then** 返回 502 与 `MODEL_OUTPUT_INVALID`，前端不展示任何字段，不把非结构化文本当作解析结果展示或入库

**AC-8 异常：未抽到任何有效字段**（对应 FR-5）

- **Given** 一份纯图片扫描件 PDF，可提取文本为空
- **When** 解析流程执行完毕
- **Then** 返回 422 与 `NO_VALID_FIELD`，不生成空档案，学生可改用其他文件重新上传

**AC-9 异常：失败时现有档案不被破坏**（对应 FR-8）

- **Given** 学生已有确认过的档案 A，档案 A 含 3 段实习经历
- **When** 上传新简历但在解析阶段超时失败
- **Then** 档案 A 的 3 段实习经历、其他字段与确认状态全部保持不变，画像模块读取到的仍是档案 A

## 功能需求

> 编号规则：FR 按用户故事分组，一个故事对应一组、每组 1–3 条，编号连续，便于 AC 逐条指回。
> 错误码约定：错误码在本节定名（大写蛇形），对应的 HTTP 状态码、响应体与触发条件在「边界与异常」表中给出，本节不重复。

### US-1 建档 → FR-1 ～ FR-3

**FR-1 简历接收**
学生可上传一份简历文件，格式限定 PDF 与 Word（.doc、.docx）。同一学生任意时刻只有一份有效档案。

**FR-2 上传校验**
文件进入流程后先校验三项：扩展名与实际文件类型是否一致、文件大小是否不超过 10MB、文件是否可正常读取。任一项不通过即终止流程，返回对应错误码与可读提示，且不写入任何档案数据。三项失败分别对应 `RESUME_FORMAT_UNSUPPORTED`、`RESUME_TOO_LARGE`、`RESUME_UNREADABLE`。

**FR-3 文件存储**
文件以随机生成的文件名保存，不使用学生上传时的原始文件名；文件访问必须经过身份鉴权，不提供任何免鉴权的直接访问地址。

### US-2 纠错确认 → FR-4 ～ FR-6

**FR-4 解析调用**
解析由大模型完成，要求输出结构化 JSON 并经 JSON Schema 校验通过后才进入下一步。调用超时固定 30 秒，失败最多重试 2 次、间隔 1 秒；重试后仍失败即判定本次解析失败。超时重试耗尽返回 `PARSE_TIMEOUT`；模型输出不是合法 JSON 或未通过 JSON Schema 校验返回 `MODEL_OUTPUT_INVALID`。

**FR-5 字段抽取**
解析结果至少包含教育背景、专业技能、项目经历、实习经历四类字段，每类按统一字段结构返回。简历中不存在某类内容时以空数组返回，不省略字段；四类字段全部为空、未抽到任何有效内容时，返回 `NO_VALID_FIELD`，不生成空档案。

**FR-6 回显与确认**
四类字段以可编辑表单回显，学生可逐项修改、删除条目或新增条目。回显内容在确认前只存在于暂存区；经学生显式确认后才写入正式档案，未确认的内容任何模块都不得读取。

### US-3 档案替换 → FR-7 ～ FR-8

**FR-7 档案替换**
学生重新上传并确认后，新档案整体替换旧档案。系统不保存、不展示、不比对任何历史版本，也不提供版本回滚。

**FR-8 现有档案保护**
上传或解析链路上任一步失败（格式不符、大小超限、文件不可读、模型超时、结构校验不通过、未抽到有效字段），当前有效档案保持上传前的状态并可继续使用，不得被部分覆盖或清空。

## 非功能需求

**NFR-1 响应与等待反馈**
上传校验结果在 5 秒内返回。解析期间前端必须持续展示进行中状态，不允许出现无反馈的空白等待。按 FR-4 的超时与重试策略，单次解析端到端最坏耗时约为 92 秒（30 秒 × 3 次 + 两次 1 秒间隔），该时长内不得让用户误以为请求已失效。

**NFR-2 隐私与日志**
简历原文与解析结果不得写入应用日志。确需排查问题时，只记录文件标识、耗时与错误码，不记录简历正文、手机号、身份证号等个人信息，也不将上述信息写入大模型 prompt。

**NFR-3 可观测性**
每次解析请求记录 requestId、开始与结束时间、总耗时、是否发生重试、最终错误码（如有），使单次解析失败的原因可以被回溯到具体环节。

## 边界与异常

| 场景 | 预期行为 | 状态码 / 错误码 | 对应 AC |
| --- | --- | --- | --- |
| 上传 .png / .jpg / .txt 等非 PDF、Word 文件 | 拒绝，不落盘、不建档 | 415 / `RESUME_FORMAT_UNSUPPORTED` | AC-5 |
| 扩展名是 .pdf，实际内容是图片或压缩包 | 按实际文件类型判定并拒绝 | 415 / `RESUME_FORMAT_UNSUPPORTED` | AC-5 |
| Word 文档设置了打开密码 | 视为不可读并拒绝 | 415 / `RESUME_UNREADABLE` | AC-5 |
| 文件为 0 字节或已损坏无法打开 | 视为不可读并拒绝 | 415 / `RESUME_UNREADABLE` | AC-5 |
| 文件大小超过 10MB | 拒绝并提示「单份简历不超过 10MB」 | 413 / `RESUME_TOO_LARGE` | AC-3 |
| 大模型连续三次均在 30 秒内无响应 | 重试 2 次后放弃，档案不变 | 504 / `PARSE_TIMEOUT` | AC-6 |
| 模型返回自然语言而非 JSON，或缺失必填字段 | 校验失败即终止，不展示半成品 | 502 / `MODEL_OUTPUT_INVALID` | AC-7 |
| 解析成功但四类字段全部为空 | 不生成空档案，提示重新上传 | 422 / `NO_VALID_FIELD` | AC-8 |
| 已有确认档案时上传新简历，解析失败 | 旧档案字段与状态保持不变 | 同对应错误 | AC-9 |

## Non-Goals

- 不生成求职画像、不做岗位匹配与推荐（属 module-02、module-03）
- 不解析非简历文档，如成绩单、证书、作品集、求职信
- 不做多份简历的并存管理、版本对比与回滚
- 不提供简历模板、排版美化与导出
- 不做简历评分、诊断与优化建议
- 不做图片简历的 OCR 识别，MVP1 只处理可提取文本的 PDF 与 Word
- 不做企业端查看、下载与导出学生简历
