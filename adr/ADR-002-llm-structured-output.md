# ADR-002: 大模型结构化输出（超时、重试与降级）

## 状态
已接受 (Accepted)

## 背景
本系统在 M1（简历解析）等模块需调用大模型抽取结构化数据。大模型 API 存在网络延迟、输出格式不稳定等风险。为保证系统健壮性，需定义统一的结构化输出约束与失败降级策略。

## 决策
1. **超时与重试**：大模型调用超时固定为 30 秒，失败重试最多 2 次，重试间隔 1 秒。
2. **输出校验**：大模型必须返回结构化 JSON，并在服务层强制通过 JSON Schema 校验。
3. **降级处理**：若重试耗尽仍超时，返回 `504, PARSE_TIMEOUT`；若输出无法通过 Schema 校验，返回 `502, MODEL_OUTPUT_INVALID`。降级时不得将半成品数据写入数据库，保留用户原状态不变。

## 备选方案
- **备选 A（异步队列 + 回调）**：
  - 优点：用户不用等待，后端压力小。
  - 缺点：架构复杂度极高，前端需轮询，MVP1 演示成本太高。
  - 适用场景：高并发、大文件批量处理。
- **备选 B（同步请求 + 降级重试）**：
  - 优点：实现简单，对前端友好，实时反馈。
  - 缺点：用户需等待最多 90 秒（30秒 × 3次），可能阻塞线程。
  - 适用场景：MVP1 单实例、演示场景、数据量不大。

## 决策依据 (Trade-off)
选择 **备选 B**。MVP1 阶段数据量小且为演示，架构需尽可能简单。超时和重试机制在服务层完成，前端只需展示 loading 和提示错误即可。
